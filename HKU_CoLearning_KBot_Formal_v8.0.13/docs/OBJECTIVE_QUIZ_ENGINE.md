# MCQ, True/False and Matching quiz engine

Based on main 708a805. This change covers question selection/generation and
post-submission explanation for the three objective types.

## Selection

The student still selects a chapter. The topic field is optional. Search stays
inside that chapter and question type, excludes served fingerprints, and ranks
both teacher Excel uploads and active JSON-bank items:

1. Case-insensitive exact topic.
2. Unicode/punctuation-insensitive topic: E-commerce, Ecommerce and E commerce.
3. Nearest topic by character similarity, with question-word overlap as a
   secondary signal for banks whose topic field is blank.

Exact matches outrank approximate matches across both bank stores; Excel wins
ties. An empty topic samples eligible questions. There is no arbitrary newest
200-row cutoff. A nearest result includes a student-visible notice and the
matched topic; a repeated request for the saved draft preserves that notice.
This is lexical similarity, not semantic embedding search. If every available
topic is unrelated, the nearest eligible question is still returned, as requested,
with the notice. Empty/exhausted pools retain the existing generation path.

Uploaded MATCH questions now enter the student flow. Their saved stable IDs
are mapped to shuffled right-side choices without truncating the 2–20 pairs
supported by the teacher template. Missing or invalid mappings are skipped.

## Question generation

The dynamic prompt now asks the generator to choose an assessment approach
from the actual focus relationship, establish the answer/explanation first,
and check answer uniqueness. MCQ tests a definition, function, comparison or
evidence-supported application. TF tests one proposition and changes one
bounded detail for a false statement. Matching uses explicit, unambiguous
relations in one coherent category.

Backend checks reject “this chapter is relevant/important/useful” questions
and options, even if an Agent ignores the prompt. Source-fact selection also
rejects those meta-statements. Existing grounding validation, local recovery,
Agent routing and timeout behavior remain in use. Existing configurable
COZE_QUIZ_TYPES still determines which types use the external Agent; this change
does not enable extra external calls.

Non-bank generated questions display `AI 生成 · Generated by AI`. A bank row
whose saved source explicitly identifies AI generation also retains an AI label.
Teacher-authored rows keep `From question bank`.

## Feedback

MCQ/TF feedback states the selected option, correct answer, and saved explanation.
No invented explanation of a distractor is added. Matching returns per-pair
selected/correct values and feedback; the visible summary explains each wrong
pair. Scoring remains deterministic, including partial matching credit. Numeric
option zero is preserved for grading and attempt storage.

Keys, mappings, explanations and citations remain private until submission.
Existing progression remains: incorrect objective answers retry that stage;
correct answers advance to the next stage.

## Verification and deployment

Acceptance coverage includes case/punctuation/typo search, blank topic, exhausted
pools, chapter/type isolation, exact JSON versus approximate Excel precedence,
older exact matches beyond 200 rows, uploaded Matching scoring, AI labels,
question-quality rejection, draft reuse, private answer keys and HTTP submission.

No database migration or new dependency is needed. Rebuild the student service
with the reviewed code and its static assets. Do not clear existing application
or knowledge data. The live Coze Agent and production deployment have not been
changed or verified by this work. The Markdown runtime prompt is authoritative
for this change; the historical platform-prompt DOCX is unchanged.
